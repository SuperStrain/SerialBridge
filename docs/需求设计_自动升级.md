# 新需求设计文档：软件自动升级（设计稿 v1，待评审）

> 状态：**待用户评审，未实施**
> 参考对象：Chrome/VS Code（后台静默+重启生效）、Notepad++（提示+跳转）、Inno Setup 生态（内置升级脚本）的混合模式。

---

## 1. 需求目标

1. 软件启动时及运行中**定期检查新版本**（GitHub Releases 为唯一发布源，与现有 CI 发布链天然衔接）。
2. 发现新版本后**非打扰式提示**（托盘气泡 + 界面角标），用户确认后自动完成下载、安装、重启。
3. 下载与安装过程**安全可回退**：校验、断点、失败不影响现有安装。
4. 绿色版（Portable）同步支持：提示 + 引导下载（不自动替换自身文件）。

---

## 2. 方案选型（结论先行）

| 方案 | 评估 | 结论 |
|---|---|---|
| **Inno Setup 内置升级脚本模式** | 下载新 Setup.exe → 静默运行 `/SILENT /CLOSEAPPLICATIONS` → 完成后重启应用。Inno 官方成熟的"下载安装器"模式 | ✅ **采用**（与现有安装链零冲突，保留卸载入口/配置迁移等全部既有行为） |
| Squirrel.Windows | 增量更新体验最好，但要求特定打包结构（.nupkg），需重构现有 Inno 安装包与卸载注册 | ❌ 不采纳（改造成本高、与 Inno 双轨维护） |
| 自研解包替换 | 运行中自替换 exe 需要第二个进程接力，出错即"砖" | ❌ 不采纳（风险不成比例） |
| Portable 绿色版 | 无法自动替换自身，只做"新版本提示 + 打开下载页" | ✅ 引导模式 |

## 3. 功能设计

### 3.1 版本检查

- **数据源**：GitHub Releases API `https://api.github.com/repos/SuperStrain/SerialBridge/releases/latest`
  （公开接口、无需鉴权、与现有发布流程零耦合）
- **时机**：启动后 30 秒（避开启动高峰）+ 每 6 小时一次 + 手动"检查更新"按钮
- **版本比较**：语义化比较（`v1.2.2` → 1.2.2；`prerelease=true` 与 `draft=true` 的 Release 忽略）
- **频率控制**：本地记录"最近一次检查时间"，每次运行最多自动检查一次（手动不受限）；
  用户提供"跳过此版本"选项（记住该版本，不再提示）
- **网络容错**：无网络/超时（5s）/接口异常 → 静默跳过，不打扰用户

### 3.2 升级流程（安装版）

```
发现新版本 → 托盘气泡 + 主界面横幅"新版本 vX.Y.Z 可用" + 设置页入口
    ├─ 用户点击"立即升级" →
    │   1. 下载 Setup.exe 到 %Temp%\SerialBridge\update\（带进度条，可取消）
    │   2. 校验：文件大小 > 10MB 且扩展名 .exe（GitHub Release 资产目前无哈希，vNext 增加_sha256 资产）
    │   3. 提示"升级将关闭程序"→ 确认后：
    │      启动 Setup（/SILENT /CURRENTUSER|ALLUSERS /RESTARTAPPLICATIONS）
    │      Setup 自动关闭本程序 → 覆盖安装（保留配置）→ 自动重启本程序
    └─ 用户点击"稍后" → 下次启动再提示（同版本只提示一次）
```

- `/RESTARTAPPLICATIONS` 为 Inno 原生支持：安装完成自动重启被关闭的应用，无缝衔接
- 安装器本身已含：运行中自动关闭程序（v1.2.1 修复）、配置保留、卸载入口更新

### 3.3 绿色版（Portable）

- 发现新版本 → 气泡与横幅提示 + "打开下载页"按钮（跳转 Release 页）
- 不做自动替换（自我文件替换需要接力进程，风险高）；设置页说明绿色版升级方式

### 3.4 设置项（设置页"关于"区）

| 项 | 默认 | 说明 |
|---|---|---|
| 自动检查更新 | 开 | 关闭后仅手动检查 |
| 当前版本 | — | 展示 + "检查更新"按钮（检查中转圈/结果显示） |

### 3.5 界面呈现

| 状态 | 呈现 |
|---|---|
| 检查中 | 设置页按钮文字"检查中…" |
| 有新版本 | 托盘气泡一次 + 主界面顶部横幅（版本号 + 立即升级/稍后/跳过此版本）+ 设置页"当前 vX.Y.Z，可用 vA.B.C" |
| 已是最新 | 设置页按钮旁文字"已是最新版本" |
| 升级中 | 横幅变为进度条（下载百分比），完成后倒计时自动执行安装 |
| 升级失败 | 横幅提示失败原因 + "打开下载页手动升级"兜底链接 |

## 4. 安全与稳定性

1. **仅 HTTPS GitHub Releases** 单一来源；不执行任何脚本。
2. **不校验代码签名**（本程序自身未签名，无意义），但保留校验链：vNext 在 CI 中输出 `_sha256.txt` 资产并在升级前校验。
3. **升级器容错**：Setup 启动失败（权限/文件锁）→ 提示用户手动运行已下载的安装包（路径给出）。
4. **回退**：Inno 覆盖安装失败会保留原程序目录；配置目录独立于程序目录，任何情况下不受影响。
5. **权限**：`/CURRENTUSER`（用户级安装）无需 UAC；`/ALLUSERS`（Program Files）触发一次 UAC——按**当前安装位置自动判断**传递对应参数。

├── Services/
│   └── UpdateService.cs        # 版本检查（HttpClient + GitHub API）、下载（进度事件）、

- **UpdateService 独立可测**：注入"版本比较函数 + HTTP 源"，单测覆盖比较逻辑与跳过策略。
- 界面新增主窗口横幅（`InfoBar`，WPF-UI 原生控件）与设置区两个元素。
