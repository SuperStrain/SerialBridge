# SerialBridge 用户使用指南

> **让同一局域网内的 AI Agent、开发者与脚本通过 TCP 访问真实设备的串口。**
>
> SerialBridge 是运行于 Windows 的串口 ↔ TCP 双向透明桥接工具。它把本机物理 COM 端口（包括 USB 转串口）映射为 TCP 监听端口，让局域网内的 AI Agent 能读取嵌入式设备日志、发送经授权的诊断命令，并根据设备反馈继续分析和排查问题，减少人工复制日志、转发命令的操作。

## 1. 安装与系统要求

从 [GitHub Releases](https://github.com/SuperStrain/SerialBridge/releases/latest) 下载最新版本，不需要寻找旧版固定文件名：

| 版本 | 文件名样式 | 使用方式 |
| --- | --- | --- |
| 安装版（推荐） | `SerialBridge-Setup-<版本>-x64.exe` | 运行安装向导，支持快捷方式、卸载和自动更新接力 |
| 便携版 | `SerialBridge-Portable-<版本>-win-x64.zip` | 解压后运行 `SerialBridge.exe`；更新时按提示手动下载新包 |

**环境要求：** Windows 10 1809 / Windows 11，x64（项目目标平台；具体兼容性以实际设备验证为准）。官方发布物为自包含构建，无须额外安装 .NET Runtime。使用内置终端时需要 Microsoft Edge [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。

SerialBridge 本身无需额外安装虚拟串口驱动，但 **CH340、CP210x、FTDI 等 USB 转串口设备可能需要厂商驱动**。先在 Windows 设备管理器确认 COM 口存在。安装时可选择创建桌面快捷方式；如果跨电脑连接被 Windows 防火墙阻挡，可使用主界面的“添加防火墙规则”或按最小权限手动放行对应端口。

## 2. 快速开始：COM3 映射到 TCP 9001

以 Windows 电脑连接一块嵌入式开发板为例：

1. 打开 SerialBridge，点击 **新增映射**。
2. 配置映射名称（例如“开发板调试串口”）、物理串口 `COM3`、实际设备波特率（例如 `115200 8N1`）、监听地址和端口 `9001`。单人或单 Agent 调试建议采用**单客户端模式**。
3. 点击 **保存**，再点击映射卡片的 **启动**，确认串口正常打开、TCP 端口处于监听状态。
4. 在同一局域网中的另一台电脑上连接 Windows 主机的实际 IP，例如 `192.168.1.100:9001`。

```text
AI Agent / Linux / 其他 TCP 客户端
           │  TCP 192.168.1.100:9001
           ▼
 Windows 电脑：SerialBridge
           │  COM3 @ 115200 8N1
           ▼
   USB 转串口 ── 开发板调试 UART
```

`0.0.0.0` 表示在 Windows 电脑上**监听所有网卡**，不是客户端的连接目标。实际连接应使用主界面提供的“客户端连接地址”。如只允许某网卡连接，选择该网卡的实际本地 IP，并同时限制防火墙访问来源。

**注意：** TCP 连接成功不代表开发板已经启动、登录成功或 Shell 已就绪。设备可能仍在 U-Boot、登录提示符或执行长耗时命令。

## 3. AI Agent 通过 TCP 调试设备

这是 SerialBridge 的主要设计场景：**AI Agent 在局域网内远程读取真实硬件的串口输出，并可在用户授权范围内发送命令。** SerialBridge 只提供字节级通道；命令执行、日志理解、下一步决策由外部 Agent 或脚本完成。

### 3.1 推荐方式：serial-tcp-uart Agent Skill

仓库自带 [serial-tcp-uart Skill](../skills/serial-tcp-uart/SKILL.md) 及 [Python 3 脚本](../skills/serial-tcp-uart/scripts/serial_session.py)，用于 Agent 通过 TCP 与串口设备交互，包括连接错误处理、显式登录、提示符等待、超时和读取输出。脚本使用 Python 3 标准库。

在 Agent 所在的 Linux 电脑上获取仓库后，可以直接测试：

```bash
python3 skills/serial-tcp-uart/scripts/serial_session.py \
  --host 192.168.1.100 --port 9001 exec "uname -a"
```

例如，获取嵌入式 Linux 内核版本与设备状态：

```bash
python3 skills/serial-tcp-uart/scripts/serial_session.py \
  --host 192.168.1.100 --port 9001 exec "cat /proc/version"
```

若设备需要登录，请按 Skill 文档配置 `--login`、`--password` 和 `--prompt`。**不要把真实密码写进共享的文档、仓库或公开日志**；命令行传入密码还可能被本机进程列表或历史记录记录，应视环境采用更安全的凭据传递方式。

### 3.2 推荐的 Agent 调试工作流

1. **确认目标：** 明确 Windows 主机 IP、TCP 端口、物理 COM 口及目标设备。
2. **建立会话：** 连接 TCP，识别 U-Boot、登录界面或 Shell 提示符；不要把“收到一次数据”当作命令完成。
3. **只读诊断：** 先执行 `uname -a`、`cat /proc/version`、`dmesg | tail` 等低风险命令并收集输出。
4. **分析反馈：** 根据输出确认内核版本、设备节点、服务状态及错误信息，再决定是否需要继续查询。
5. **人工授权：** 重启设备、停止服务、修改配置或烧写 Flash 等会改变设备状态的操作，先获得用户明确同意。
6. **结束并释放：** 完成后主动断开 TCP 会话，避免占用单客户端映射。

单客户端模式下，同一时刻只能有一个 TCP 客户端。已有连接时，新连接可能立即被服务端关闭；Agent 不应无限重试或抢占人工调试会话。若需并发访问，可评估多客户端模式，但**不会自动对不同客户端的命令与响应进行配对**。

### 3.3 发送原始字节

无需 Shell 时也可以发送二进制命令。例如发送 `AT\r` 并监听两秒：

```bash
python3 skills/serial-tcp-uart/scripts/serial_session.py \
  --host 192.168.1.100 --port 9001 raw --hex "41 54 0d" --wait 2
```

串口是原始字节流，不提供 TCP 消息边界或命令完成标记。Shell 提示符匹配只是一种常见的同步策略；若有异步日志、自定义提示符或设备无 Shell，应调整解析逻辑，不能据此直接认定命令执行成功。

## 4. 内置串口终端

在映射卡片上点击**串口终端**按钮（对话气泡图标），可直接在 SerialBridge 内与对应串口交互，无须额外 TCP 客户端。终端使用 WebView2 + xterm.js，可显示设备输出并逐键发送输入，包括 Tab、Ctrl+C 和方向键。

| 操作 | 使用方法 |
| --- | --- |
| 搜索终端历史 | 点击 **搜索** 或使用 `Ctrl+F`，`F3` 查找下一处 |
| 历史滚动 | 上翻查看历史时暂停自动跟随；点击 **回到底部** 继续跟随 |
| 清屏 | 点击 **清屏**，只清除显示，不清理设备输出或重启设备 |
| 字体缩放 | `Ctrl++` / `Ctrl+-` / `Ctrl+0`，或 `Ctrl+鼠标滚轮` |
| 复制/粘贴 | `Ctrl+Shift+C` / `Ctrl+Shift+V` |
| 快捷命令栏 | 点击 **快捷命令 / 宏** 显示或隐藏 |

这里是**串口控制台**，不是在 Windows 本机执行命令；终端显示与回显由串口设备决定。内置终端无法加载时，检查 WebView2 Runtime 是否安装。

## 5. 快捷命令与宏

打开串口终端 → **快捷命令 / 宏** → 底部命令栏 **编辑**，即可创建预设。一个步骤对应快捷命令，多个步骤组成按顺序发送的宏。

| 字段 | 含义 |
| --- | --- |
| `Text` | 将文本编码为 UTF-8 后发送 |
| `Hex` | 精确发送十六进制字节，例如 `01 03 00 FF` |
| `None` | 不追加结束字节 |
| `CR` | 回车 `0D`，常见 Linux 串口控制台的 Enter |
| `LF` | 换行 `0A` |
| `CRLF` | 回车换行 `0D 0A` |
| 延时（ms） | 发送当前步骤后等待指定毫秒数，再继续下一步 |

例如创建文本命令 `uname -a`、结束方式 `CR`，保存后点击命令栏对应按钮，即可向**当前映射的串口**发送。

宏支持逐步执行及取消后续步骤，但**不会自动等待设备提示符或实际命令完成**；已经加入队列或发送出去的字节无法撤回。HEX 步骤不追加换行；宏运行期间其他客户端及人工终端仍可能发送数据。详细配置、限制和风险见 [《快捷命令与宏》](快捷命令与宏.md)。

不要将 `reboot`、擦除 Flash 等高风险命令做成易误触的无确认快捷按钮。预设保存在本机 `config.json`，其中的敏感口令目前不是安全凭据存储。

## 6. 数据监控与串口日志落盘

这两项功能用途不同：

### 6.1 实时数据监控

点击映射卡片上的 **数据监控** 图标，可查看 TCP → 串口以及串口 → TCP 的数据，包括方向、时间戳、HEX / ASCII 内容与收发统计。支持暂停显示、清屏和导出。

实时监控为**有限显示缓存**，缓存较老或截断的内容不能视为持久、完整的原始通信存档。暂停监控显示不等于暂停通信。

### 6.2 持久化串口日志

编辑映射，在 **串口日志** 区域启用落盘并选择存储目录：

| 配置项 | 说明 |
| --- | --- |
| 文本模式 | 类似 Xshell 的设备输出日志；适合查看启动信息、Shell 输出 |
| HEX 模式 | 按时间戳和方向记录双向收发数据；适合分析二进制协议 |
| 文本编码 | UTF-8 或 GBK（老设备）；GBK 转换适合可解码文本 |
| 保留天数 | 配置范围 7–365 天 |
| 单文件上限 | 配置范围 10–500 MB，超过后分卷 |

日志按日期与大小轮转，并按配置清理旧文件。主界面映射卡片上的日志状态提示可用于打开日志目录。

**区分运行日志和串口数据日志：** 应用运行错误、连接状态等写入程序日志目录；设备 UART 的文本或 HEX 记录保存在该映射所选择的数据日志目录。需要字节级复核时选择 HEX，不应依赖文本解码表示无损二进制数据。

## 7. 串口与 TCP 参数

- **串口参数：** COM 口、波特率、数据位、停止位、校验与流控必须与设备匹配；典型调试串口为 `115200 8N1`、无流控，但应以设备实际设置为准。
- **监听地址：** `0.0.0.0` 监听全部本地 IPv4 网卡；指定 Windows 主机 IP 可限制监听接口。客户端不能以 `0.0.0.0` 为目标地址。
- **单客户端（推荐）：** 同时只接受一个 TCP 客户端，适合 Agent、开发者独占调试。其他客户端可能连接后马上被拒绝。
- **多客户端：** 串口输出广播给多个客户端；写入串口会串行化，但**不会区分或自动配对各客户端的请求与响应**。高频写入时应协调占用者。
- **自动重连：** USB 断开等异常可按设定重试。若串口已被其他程序占用，可能进入异常状态，需要人工排查。
- **端口冲突：** 同一物理 COM 口或相同监听端点不能被多个冲突映射同时占用。TCP 端口还可能被其他 Windows 程序占用。

TCP 是字节流而非串口协议解析器；SerialBridge 不会解释 Telnet 协商、Modbus 帧边界或 Shell 命令结果。

## 8. Linux 人工交互与其他连接方式

以下示例的 Windows 主机 IP 均为 `192.168.1.100`，映射 TCP 端口为 `9001`。连接前确保设备已启动，且没有其他客户端独占该端口。

### 8.1 推荐：socat + picocom

在 Ubuntu 上：

```bash
sudo apt install socat picocom
socat PTY,link=/tmp/ttydev,waitslave TCP:192.168.1.100:9001 &
picocom /tmp/ttydev
```

这种方式将 TCP 映射为本地伪终端（PTY），更适合 Tab 补全、Ctrl+C、方向键等交互。退出 picocom 可使用 `Ctrl+A` 再 `Ctrl+X`，之后检查并清理刚才启动的 socat 后台任务（例如 `jobs -l`、`kill %1`，避免误杀其他 socat 进程）。

picocom 显示的本地 PTY 波特率**不控制**远端物理 COM 口；真正的 UART 波特率由 Windows 端 SerialBridge 设置。也可使用 `minicom -D /tmp/ttydev`。

### 8.2 Agent / 自动化脚本：原始 TCP

需要 Agent 读取日志、等待 Shell 提示符并发送命令时，优先使用第 3 章的 Python 脚本。它使用原始 TCP，不要求用户进行交互式键盘输入。

简单的非交互探测也可使用 Python socket；不要假定一次 `recv` 就是完整响应。

### 8.3 nc、screen 与 telnet 注意事项

直接运行 `nc 192.168.1.100 9001` 在某些本地终端设置下会受到行缓冲影响，Tab 等按键不一定立即发给设备。若明确需要原始逐键输入，可暂时切换终端 raw 模式，并确保退出后恢复：

```bash
old_stty=$(stty -g)
trap 'stty "$old_stty"' EXIT
stty raw -echo
nc 192.168.1.100 9001
```

**务必恢复终端状态**；异常退出后如果终端显示异常，可运行 `stty sane`。交互体验一般仍建议 socat + picocom。

`screen //telnet 192.168.1.100 9001` 使用的是 Telnet 相关通道，并非纯原始字节连接；此前实际嵌入式设备调试中发现 Tab 补全失效。Telnet 也会将 `0xFF` 作为协议控制字节，不适合二进制透明透传。若要使用 screen，先创建 PTY，再运行 `screen /tmp/ttydev`。

## 9. 主界面、设置与自动更新

### 9.1 主界面

主界面提供映射状态、收发统计、连接客户端数量、串口和 TCP 监听信息。每张映射卡片可进行：

- **启动 / 停止**、**编辑 / 删除**；
- 打开**串口终端**或**数据监控**；
- 查看客户端详情与日志落盘状态；
- 识别“停止 / 运行中 / 重连中 / 异常”等状态。

工具栏还有 **新增映射**、**全部启动**、**全部停止**、**刷新串口**、**Linux 主机访问指南**及设置入口。局域网连接应使用映射卡片标明的“客户端连接地址”。

### 9.2 设置、系统托盘

在 **设置** 中可配置浅色 / 深色 / 跟随系统、开机自动启动、启动时自动恢复映射及自动检查更新。勾选映射的“自动运行”且启用恢复功能后，启动软件时会尝试启动该映射。

主窗口关闭按钮可将程序收起至系统托盘，映射继续运行；**真正退出应使用托盘菜单“退出”**。退出或映射停止会断开正在使用的 TCP/串口会话，Agent 必须处理连接关闭。

### 9.3 更新流程

- **安装版：** 设置 → **检查更新**（或自动检查）；有新版本时可通过主窗口提示 **立即升级**，下载匹配安装包并通过安装器接力完成更新，通常保留原用户配置。
- **便携版：** 检测到新版时主要引导前往 GitHub Releases 下载，需自行解压、替换旧版本程序。
- 网络不可用、GitHub API 限流或发布资产缺失时，检查或下载可能失败，可手动访问 [Releases](https://github.com/SuperStrain/SerialBridge/releases/latest)。

更新安装时可能需要关闭运行中的 SerialBridge 或确认 UAC 权限；更新前应先结束正在进行的设备调试会话。

## 10. 数据目录与配置

程序数据默认保存在 `%AppData%\SerialBridge`，与安装目录独立：

```text
%AppData%\SerialBridge\
├── config.json                  映射、偏好、快捷命令与宏
└── logs\                       软件运行日志
    └── serialbridge-日期.log
```

每条映射的**串口数据日志**则存储在映射配置时指定的目录，不一定在上述 `logs` 下。

更新和卸载通常**保留** `%AppData%\SerialBridge` 用户数据。当前安装器并没有提供卸载时自动删除该目录的功能；确需完全清理时，请在备份必要信息后自行删除。

配置加载失败时，程序会尝试将损坏文件另存为 `.corrupt-时间戳` 备份，并避免用默认配置覆盖原文件。快捷命令宏预设目前以本地 JSON 方式保存，**不适合存放明文真实密码或密钥**。

## 11. 常见问题

| 问题 | 排查方法 |
| --- | --- |
| AI Agent 连不上 TCP | 检查 Windows 主机 IP、映射是否启动、监听地址、端口及入站防火墙；确保处于可达的可信网络 |
| TCP 连接立即断开 | 检查是否为单客户端模式、已有终端/Agent 独占会话，或映射已停止 |
| 连接成功但没有 Shell | 设备可能未登录、提示符不匹配、处于 U-Boot、串口参数错误，或仅在收到输入后输出 |
| Agent 读取命令超时 | 调整 `--prompt` 或 `--timeout`，检查是否有异步日志或真正卡住的命令；不要自动判定命令执行失败 |
| 串口端口无法打开 | 检查设备管理器中的驱动、COM 号和其他终端程序的占用 |
| USB 拔插后未恢复 | 刷新串口列表，检查重新枚举的 COM 号、重连设置及设备状态 |
| 内置终端无法显示 | 检查 WebView2 Runtime 是否安装、终端初始化错误以及串口连接状态 |
| 宏只发送第一步 | 检查延时、串口断开、停止映射、队列满或宏被取消；宏不会自动等待提示符 |
| Tab、Ctrl+C 不生效 | 避免 Telnet 协商和 nc 行缓冲；优先使用内置终端或 socat + picocom |
| 实时监控缺失旧数据 | 显示缓存有上限；需要留存完整业务会话时应提前开启串口日志落盘 |
| 更新失败 | 检查网络、GitHub Release 资产、磁盘权限及安装器权限，必要时手动下载安装包 |

## 12. 安全与使用边界

**SerialBridge 的原始 TCP 桥接没有内置加密或客户端身份认证，不应直接开放到公网。** 建议仅在可信局域网内使用，优先绑定必要的网卡 IP，并通过 Windows 防火墙限制来源。对高权限调试设备应采取额外网络隔离。

AI Agent 经 TCP 发送的字节与人工在串口终端键入的字节具有同等设备侧效果。因此：

- 默认只允许只读诊断；修改配置、重启、控制硬件、清除数据、烧写固件等操作应获得用户明确授权。
- 不要把凭据和敏感串口日志提交到公开仓库、复制到共享对话或保存在宏明文预设中。
- Agent 发现端口被占用时应协调释放，而不是强行重连或启动新的写入会话。
- 多客户端不保证跨客户端事务隔离、命令与响应配对，也不应作为多 Agent 协调机制。
- 连接成功或检测到 Shell 提示符，不等于命令成功；需要结合实际输出进行判断。

SerialBridge 是**串口传输基础设施**，不包含内置 AI 模型、自动推理或完整的 Agent 工作流引擎。对设备的访问和操作范围取决于外部客户端及用户授权。
