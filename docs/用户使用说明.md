# SerialBridge 用户使用说明

SerialBridge（串口网络桥接工具）把 Windows 本机的物理串口（COM 口，含 USB 转串口）桥接到 TCP 监听端口，实现双向透明数据转发。局域网内的设备通过 `本机IP:端口` 即可与串口设备通信，无需安装驱动，也无需互联网。

## 1. 安装

1. 双击 `SerialBridge-Setup-1.0.0-x64.exe`。
2. 按向导选择安装位置（默认 `C:\Program Files\SerialBridge`），可勾选创建桌面快捷方式。
3. 首次弹出防火墙提示时选择"允许访问"，或直接使用软件内的"添加防火墙规则"按钮。
4. 安装完成即写好 Windows 卸载入口，可在"设置 → 应用"中卸载。

**系统要求**：Windows 10 1809 / Windows 11 及以上，x64。运行时已内置于安装包，无需另装 .NET。

## 2. 快速上手（3 步）

以"把 COM3 桥接到 9001 端口"为例：

1. 主界面点击 **新增映射**。
2. 填写配置：
   - 映射名称：随意，如 `一号设备`
   - 物理串口：选择 `COM3`，设置波特率等参数（默认 115200 8N1）
   - 监听地址：保持 `0.0.0.0`（监听所有网卡）
   - 监听端口：`9001`
   - 客户端模式：单客户端（默认，推荐）
3. 点击 **保存**，再点卡片上的 **启动**。

之后局域网内任意设备连接 `192.168.x.x:9001`（主界面会显示本机所有可用地址）即可与 COM3 上的设备收发数据。

## 3. 主界面

顶部四张统计卡片显示运行映射数、TCP 客户端总数、累计收发数据量。

每条映射卡片显示：

| 项目 | 说明 |
|---|---|
| 状态徽章 | 运行中 / 已停止 / 串口重连中 / 串口异常 / 启动失败 |
| 串口摘要 | 如 `COM7 @ 115200 8N1` |
| 监听地址 | 本机监听的 IP 与端口 |
| 客户端连接地址 | 局域网设备应使用的地址（自动枚举所有网卡，切勿使用 0.0.0.0 连接） |
| 收发统计 | ↓ 设备→网络，↑ 网络→设备 |

操作按钮：**启动/停止**、**数据监控**、**编辑**、**删除**。

## 4. 数据监控

点击卡片的监控按钮（⇄ 图标）打开独立窗口：

- **HEX / ASCII** 两种显示模式，随时切换。
- **↓ IN**（蓝色）= 网络→串口（客户端下发）；**↑ OUT**（绿色）= 串口→网络（设备上传）。
- 每条记录带毫秒时间戳。
- **暂停**：停止刷新显示（统计仍累计）；**清空**：清屏；**导出**：把当前记录导出为 TXT（同时含 HEX 与文本两行）。
- 显示缓存上限 3000 条、单条最多捕获 8KB，自动丢弃最旧记录，不影响通信本身。

## 5. 串口与 TCP 参数说明

- **波特率/数据位/停止位/校验/流控**：与对端设备保持一致。流控一般选 None。
- **监听地址**：
  - `0.0.0.0`：监听所有网卡（推荐，多网卡环境均可访问）。
  - 指定某网卡 IP：仅该网段可访问（可用于隔离网络）。
- **客户端模式**：
  - **单客户端（默认）**：同一时间只允许 1 个客户端。新连接会被立即拒绝并记日志。适合大多数仪器与 PLC 场景。
  - **多客户端**：最多 N 个客户端同时在线；串口数据广播给所有客户端；多个客户端的数据按先后顺序写入串口。注意：**不同客户端的请求/响应不会自动配对**，请确保应用层协议本身不会冲突。
- **自动重连**：串口意外断开（USB 拔出等）后按设定间隔自动重试；串口被其他程序占用时不会盲目重试，会显示"串口异常"等待人工处理。

## 6. 设置与系统托盘

- **主题**：浅色 / 深色 / 跟随系统。
- **开机自启动**：写入当前用户注册表 Run 项，启动后最小化到托盘。
- **启动时自动恢复映射**：重启软件后恢复全部映射；勾选了"自动运行"的映射自动启动。
- **最小化到托盘 / 关闭时隐藏到托盘**：托盘运行时串口与 TCP 转发持续工作。托盘右键菜单可快速启动/停止全部映射或退出。

## 7. 数据目录

配置与日志保存在 `%AppData%\SerialBridge`（即 `C:\Users\<用户名>\AppData\Roaming\SerialBridge`），与程序目录分离：

- `config.json` — 全部映射与偏好设置
- `logs\serialbridge-日期.log` — 运行日志（按天滚动，保留 30 天）

升级重装不会丢失配置；卸载时会询问是否删除。

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| 局域网设备连不上 | 1) 确认使用主界面显示的局域网 IP 而非 0.0.0.0；2) 点击"添加防火墙规则"或手动放行；3) 确认客户端与主机在同一网段 |
| 串口状态"串口异常：被占用" | 关闭占用该串口的其他程序，再点"启动" |
| 串口列表没有新插入的设备 | 点工具栏"刷新"，或重启软件 |
| 映射启动失败：端口被占用 | 更换监听端口，或停止占用该端口的程序 |
| 客户端频繁断开 | 检查网络稳定性；串口→网络方向可正常重连 |
| 连接后无数据 | 检查波特率等串口参数是否与设备一致；用数据监控窗口观察双向数据 |

## 10. 从 Linux 主机访问（Ubuntu 等）

局域网内的 Linux 主机通过 TCP 连接映射端口即可与串口设备双向通信。**推荐方式按交互体验排序如下**（连接地址用 SerialBridge 主界面显示的局域网 IP，下例以 `192.168.1.100:9001` 为例）：

### 方式一：socat + picocom / minicom —— 交互体验最优（推荐日常调试）

socat 把 TCP 映射成本地虚拟终端（PTY），picocom/minicom 按真实串口终端的方式操作它——补全、Ctrl+C、Vi 等行为与物理接线完全一致：

```bash
sudo apt install socat picocom
socat PTY,link=/tmp/ttydev,waitslave TCP:192.168.1.100:9001 &
picocom /tmp/ttydev          # minicom -D /tmp/ttydev 亦可
# 退出 picocom: Ctrl+A 然后 Ctrl+X
```

看到 `Terminal ready` 即已连上，可直接操作设备。两点说明：
- picocom 打印的 `baudrate 9600` 等参数只是本地虚拟终端的显示值，
  与通信无关——实际波特率由 Windows 侧 SerialBridge 的映射配置决定；
- 后台 socat 实例在连接断开（如 picocom 退出）后会自行退出，bash 的
  "[n] 已完成 socat ..." 通知属于正常现象，不代表出错。

会话结束后清理：`kill %1` 或 `pkill socat`（socat 挂在后台时即使 picocom
已退出也会继续占用连接，用完记得清理）。

### 方式二：screen —— ⚠️ 实测 Tab 补全失灵，不推荐用于本软件

Ubuntu 自带的 GNU screen 通过内置的 `//telnet` 伪设备连接 TCP
（注意：不能直接写 `screen IP 端口`，screen 会把第一个参数当作要执行的程序，
报 "Cannot exec 'IP'"）：

```bash
screen //telnet 192.168.1.100 9001
```

但实测（海思板 + busybox ash，2026-10）**该方式下 Tab 补全失灵**：
screen 的 telnet 协议栈与"哑透传"对端（SerialBridge 不应答 telnet 协商）
先天不匹配，按键未到达设备。链路本身已用原始 TCP 验证正常（逐字符发送
`ifc`+Tab，设备立即回发 `
~ # ifconfig [J` 补全重绘）。需要 screen 体验时，
请用方式一组合：`screen /tmp/ttydev`（socat 先建好 PTY）。

### 方式三：脚本化访问（agent / 自动化对接）

程序对接不需要终端语义，直接用原始 socket 最可靠。配套仓库 `skills/serial-tcp-uart/scripts/serial_session.py`（Python 3 标准库）封装了占用检测、登录、提示符等待、回显剥离：

```bash
python3 serial_session.py --host 192.168.1.100 --port 9001 exec "uname -a"
```

亦可用纯 bash / python 简单对接：

```bash
exec 3<>/dev/tcp/192.168.1.100/9001; printf 'AT
' >&3; head -c 64 <&3 | xxd
```

### 方式四：nc（保留现有习惯的最小改法）

nc 的标准输入是行缓冲模式（icanon），Tab、Ctrl+C 会被本地终端攒到回车才发送——直接
`nc 主机 端口` 会出现"Tab 补全不生效"的现象。若坚持使用 nc，先把终端切成 raw 模式：

```bash
stty raw -echo; nc 192.168.1.100 9001; stty sane
# raw 模式下 Ctrl+C 会作为 0x03 发给设备（对调试串口这通常正是想要的行为）；
# nc 结束后务必执行 stty sane 恢复终端。
```

**为什么不推荐 telnet**：telnet 会把 0xFF 当作协议转义字符（IAC）处理并改写行尾，
二进制协议必坏，仅可用于纯 ASCII 手动试探。

### 单客户端与占用

映射默认为单客户端模式：同一时间仅允许一个连接，新连接会被服务端立即关闭。
多台主机/工具需要同时访问时，在映射配置里改用多客户端模式（注意：串口数据会广播给
所有客户端，多客户端写入按先后顺序串行化，但不保证不同客户端的请求响应配对）。

## 9. 安全提示

原始 TCP 透传**不包含加密与身份认证**，任何能建立 TCP 连接的程序都可以收发数据。请仅在可信局域网使用；需要隔离时使用"监听地址"限定网卡，或在路由/防火墙层面控制访问来源。
