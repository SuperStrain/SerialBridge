# 新需求设计文档：串口日志本地保存（设计稿 v1，待评审）

> 状态：**待用户评审，未实施**
> 需求来源：监控窗口仅保留最近 3000 条缓存、导出为手动操作——需要**持续、完整、自动**的串口数据落盘能力（设备通信留痕、问题追溯、协议分析）。

---

## 1. 需求目标

1. 每条映射可独立开启"串口日志"，将**双向数据流完整落盘**：
   - 设备 → 网络（OUT，设备上传）
   - 网络 → 设备（IN，客户端/终端下发，含内置串口终端）
2. 不受监控窗口缓存限制——**全部数据**（除启用前/禁用后）。
3. 长期运行友好：按天/按大小自动轮转、按保留天数自动清理，磁盘占用可控。
4. 高流量（MB/s 级）不阻塞转发路径；磁盘异常自动降级不影响通信。

---

## 2. 非目标（明确不做）

- 不做协议解析/过滤（原样记录字节）。
- 不做云端/数据库存储（本地文件）。
- 不做 PCAP 等二进制分析格式（列为未来增强）。
- 运行日志（Serilog，程序事件）保持现状，与本功能分离。

---

## 3. 存储设计

### 3.1 目录与命名

```
%AppData%\SerialBridge\captures\<映射ID短码>\
    ├── <映射名>_20261011.log
    ├── <映射名>_20261012.log
    └── ...
```

- 目录用**映射 ID**（稳定，映射改名不影响归档归属）；文件名用映射名（人类可读）。
- 映射删除时**日志保留**（历史记录价值高于整洁）；"设置"提供打开数据日志目录入口。

### 3.2 记录格式（文本，默认）

每条记录一行（长数据按行内展示，不做多行）：

```
2026-10-11 14:20:30.123 OUT 11 48 65 6C 6C 6F | Hello
2026-10-11 14:20:30.456 IN  5  31 32 33 0D     | 123
```

- 列：时间戳（本地，毫秒）· 方向（OUT=设备→网络 / IN=网络→设备）· 字节数 · HEX · ASCII（不可打印字符显示为 `·`）
- ASCII 段仅截断显示前 64 字节，HEX 段记录**完整字节**（可完整还原通信）
- 编码 UTF-8，换行 `\n`，追加模式写入

### 3.3 轮转与保留

| 策略 | 默认值 | 说明 |
|---|---|---|
| 按天轮转 | 开 | 文件名含日期，自然按天切分 |
| 按大小轮转 | 50 MB | 单文件超限即滚动为 `<名>_<日期>_001.log`、`_002` …（防止单日爆盘） |
| 保留天数 | 30 天 | 可配置（7–365）；启动时 + 每天零点后清理过期文件（仅清理本映射目录内匹配文件） |
| 磁盘余量保护 | 500 MB | 写入前检查所在盘剩余空间，低于阈值暂停记录并告警（数据不丢，恢复后继续） |

## 4. 性能与可靠性

1. **异步写入**：每条映射一个专用写任务 + 内存队列（容量 2048 块）。
   串口读循环/转发路径只做**入队 + 一次字节复制**（微秒级），绝不阻塞。
2. **批量落盘**：写任务聚合缓冲，每 500ms 或缓冲达 64KB 时 flush 一次。
3. **队列溢出**（磁盘极慢）：丢弃最旧未写块、计数告警（与慢速客户端保护同哲学：**保护通信主链路**）。
4. **IO 异常降级**：写失败（磁盘满/文件锁）→ 自动暂停记录、置告警状态、
   每 30s 重试恢复；转发链路完全不受影响。
5. **退出安全**：程序退出时 flush 并关闭文件句柄（进程内数据不丢）。

## 5. 配置与界面

### 5.1 映射配置（编辑对话框新增"串口日志"分组）

```jsonc
// MappingConfig 新增
"DataLog": {
  "Enabled": false,        // 默认关闭（用户按需开启，避免无意写盘）
  "RetentionDays": 30,     // 7–365
  "MaxFileMB": 50,         // 单文件轮转阈值（10–500）
  "Direction": "Both"      // Both / OutOnly / InOnly
}
```

### 5.2 界面呈现

| 位置 | 内容 |
|---|---|
| 编辑对话框 | "串口日志"分组：启用开关、保留天数、单文件上限、方向选择 |
| 映射卡片 | 日志状态徽标：`● 记录中`（启用且正常）/ `⚠ 日志暂停`（IO 异常/磁盘余量不足）/ 不显示（未启用）；点击打开该映射日志目录 |
| 设置窗口 | "数据日志目录"行 + "打开目录"按钮（与运行日志目录并列） |
| 运行日志 | 记录启动/轮转/异常/清理等事件（不记录数据内容） |

## 6. 实现组件

```
SerialBridge.Core/
├── Capture/
│   ├── SerialCaptureService.cs   # 每映射实例：队列 + 写线程 + 轮转 + 清理 + 降级
│   └── CaptureEntry.cs           # 时间/方向/字节 的内存块
└── Bridge/MappingRuntime.cs      # 启动/停止时创建/释放 capture；订阅 DataTransferred
```

- 数据来源：复用现有 `MappingRuntime.DataTransferred` 事件（零侵入转发路径）。
- 订阅侧**立即复制**字节（与监控同一约束，避免引用共享导致的写后改）。
- `SerialCaptureService` 独立可测：注入时间源与写入目标（测试用内存流断言格式/轮转/清理）。

## 7. 测试计划

| # | 用例 |
|---|---|
| 1 | 启用后双向数据落盘：内容含方向/字节数/HEX，与发送字节一致 |

| 3 | 跨天与超限轮转：新文件创建、旧文件保留 |
| 4 | 保留清理：过期文件删除、当日文件不误删 |
| 5 | 磁盘余量不足：暂停 + 告警状态、恢复后继续 |
| 6 | 高流量（连续 50MB）：转发速率无明显下降、无内存增长、轮转正确 |
| 7 | 映射改名/删除：日志目录与归档不受影响 |
| 8 | 程序异常退出：已 flush 数据完整、句柄无残留锁 |
