# 新需求设计文档：本地串口访问（设计稿 v1，待评审）

> 状态：**待用户评审，未实施**
> 需求来源：串口被 SerialBridge 独占后，本机的串口终端软件（Xshell、SSCOM 等）无法再访问该串口。

---

## 1. 需求背景

SerialBridge 将物理串口独占并转换为 TCP 端口后产生一个副作用：**Windows 本机**的串口软件
无法再打开被占用的物理串口——本机用户反而"失去了"对设备的直接访问能力，需要绕道局域网
IP 才能连回自己的设备，不合理也不方便。

期望：TCP 转发的同时，本机软件仍有一条访问同一设备的通路，且在界面上明确呈现；该通路
需要与现有的单客户端/多客户端模式语义相适配。

---

## 2. 技术可行性（本设计的关键结论）

"在本机虚拟出一个 COM 口"在 Windows 上必须依赖**内核模式驱动**（COM 口是内核对象，
无法在用户态伪造）。可选路线的真实情况：

| 路线 | 可行性 | 说明 |
|---|---|---|
| A. 自研虚拟串口驱动 | ❌ 不采纳 | 需要 EV 代码签名 + 微软硬件开发中心认证，成本数量级不符 |
| B. 集成 com0com（开源驱动对） | ⚠️ 可行但受限 | 免费，但驱动**无 WHQL 签名**，Win10/11 x64 默认拒绝加载，需用户接受降级（测试签名/禁用强制签名），且 com0com 为 GPL，只能作为**独立安装的可选组件**（不可捆绑进 MIT 仓库） |
| C. 商业虚拟串口 SDK（Eltima/HHD 等） | ❌ 不采纳 | 付费授权，与开源定位冲突 |
| D. **本机软件直接连 TCP（零驱动）** | ✅ 立即可行 | Xshell 支持 Telnet 会话直连本机端口；PuTTY/MobaXterm 支持 **Raw TCP**（无任何协议开销，等价真实串口）；**不需要虚拟串口** |
| E. 混合：D 立即实施 + B 作为可选实验功能 | ✅ 推荐 | 见下文分阶段方案 |

**结论**：采用 **路线 E 分阶段实施**。阶段一（零驱动本机直连）解决绝大多数诉求；
阶段二（com0com 桥接）作为面向高级用户的实验性可选功能，单独评估是否实施。

---

## 3. 方案设计

### 3.1 阶段一：本机直连（零驱动，推荐立即实施）

**思路**：本机软件不需要 COM 口——直接连 `127.0.0.1:端口` 就是同一条链路
（与远程访问共用全部现有逻辑，无新增转发路径，无新风险点）。

改动内容：

1. **映射卡片显示"本机连接"地址**：在客户端连接地址行增加
   `本机连接: 127.0.0.1:9001`（所有映射恒定可用，无需配置）。
2. **客户端详情窗口**：本机连接（127.0.0.1 来源）正常显示在列表中，与其他客户端一致。
3. **Linux 访问指南窗口增加"本机 Windows 软件"一节**：
   - Xshell：新建会话 → 协议 TELNET → 主机 `127.0.0.1` → 端口 `9001`
     （注意：Xshell 的 Telnet 模式会发协商字节，纯文本调试不受影响；二进制协议场景用下一条）
   - PuTTY / MobaXterm：协议选 **Raw**，主机 `127.0.0.1`，端口 `9001` —— 等价真实串口，
     Tab/Ctrl+C 行为与物理接线一致（Raw 无协议层）
   - SSCom 等纯 COM 口软件：无法直连 TCP，需等待阶段二（虚拟串口）或改用上述工具
4. 使用说明文档同步。

**不改变任何现有语义**：TCP 客户端计数、单/多客户端限制、慢速客户端保护对 127.0.0.1
连接与其他连接完全一视同仁。

### 3.2 阶段二：com0com 虚拟串口对桥接（实验性，可选实施）

**思路**：借助独立安装的 com0com 创建虚拟串口对（如 `COM11 ↔ COM12`），
SerialBridge 占用 COM12 作为"本地接入端"，本机串口软件照常打开 COM11。
SerialBridge 内部把数据在三方之间桥接。

#### 3.2.1 架构

```
                              ┌── TCP 客户端 1..N ──┐
物理设备 ←── 物理串口(COM7) ── SerialBridge ──┤                     │
                              │   本地虚拟口(COM12) ─┘  ←── COM11 ←── 本机串口软件
```

- **本地虚拟口是"特权本地端"**：不受 TCP 客户端数量限制。
- 三方数据路径（复用现有串口写队列与广播机制）：
  - 物理串口收到 → 广播给：TCP 客户端（按单/多客户端模式）+ 本地虚拟口（若启用且用户软件在线）
  - 本地虚拟口收到 → 与 TCP 客户端数据**共享同一条串口写队列**（严格 FIFO，杜绝交叉）
  - TCP 客户端收到 → 同上
- 设备回显语义与真实串口一致（本地软件能看到自己发出的字符回显）。

#### 3.2.2 与单客户端 / 多客户端模式的适配语义（明确约定）

| 场景 | 行为 |
|---|---|
| 单客户端模式 + 本地口启用 | TCP 侧仍只允许 1 个连接；**本地口不计入限制**、始终可打开 |
| 多客户端模式 + 本地口启用 | TCP 上限 N 不变；本地口独立于 N |
| 多方同时写入 | 全部进入同一条 FIFO 写队列，按到达顺序写入物理串口（与现有多客户端语义一致） |
| 请求/响应配对 | 与多客户端模式相同的免责：多个写入方并存时不保证配对，由上层协议自律 |
| 本地软件未打开 COM11 | COM12 侧数据积压由 com0com 缓冲承载（默认约 4KB×2），溢出即丢弃并计数告警；建议本地软件常开，或按需启用 |
| 本地口打开失败 | COM12 被 SerialBridge 打开后恒定可用；COM11 被谁打开 SerialBridge 不感知（透传） |

#### 3.2.3 com0com 生命周期管理

1. **检测**：枚举系统是否已安装 com0com（`setupc` 存在性 + `cnxx` 设备枚举）。
2. **引导安装**：未安装时在界面给出独立引导（下载官方安装包 → 用户手动安装并接受 UAC
   与驱动签名警告）。**SerialBridge 不静默安装、不捆绑驱动文件**（GPL 合规 + 降低风险）。
3. **创建/删除对**：调用 `setupc install PortPair` 自动挑选空闲端口号（避开物理口与占用口），
   删除映射时可选保留或移除该对。
4. **失败降级**：com0com 不可用（未装/驱动未加载）时映射仍正常工作，
   仅本地虚拟口功能不可用并在界面明确标注原因。

#### 3.2.4 配置模型

```jsonc
// MappingConfig 新增
"LocalVirtual": {
  "Enabled": false,          // 是否启用本地虚拟串口
  "PairName": "0",           // com0com 对编号（自动分配）
  "UserSidePort": "COM11",   // 给本机软件使用的端口（对的用户端）
  "BridgeSidePort": "COM12"  // SerialBridge 占用的端口（对的桥接端，自动分配）
}
```

## 4. 界面设计

### 阶段一
- 映射卡片"客户端连接地址"行追加：`本机连接: 127.0.0.1:9001`
- Linux 访问指南窗口新增"本机 Windows 软件"章节（Xshell/PuTTY Raw/MobaXterm 操作步骤）

### 阶段二
- 映射卡片增加状态行：`本地虚拟串口: COM11（已启用，本机软件在线/空闲）`
- 编辑对话框新增"本地虚拟串口"分组：启用开关、端口显示、（高级）更换端口号
- 客户端详情窗口：本地虚拟口的流量以独立行呈现（标注"本地"），不与 TCP 客户端混淆

## 5. 测试计划

### 阶段一
1. 卡片正确显示 127.0.0.1 地址
2. PuTTY Raw 连接 127.0.0.1 与远程连接行为一致（含 Tab/Ctrl+C）
3. Xshell Telnet 模式连通性验证（文本场景）
4. 单客户端占用语义不变（127.0.0.1 与远程互斥）

### 阶段二
1. com0com 未装时：功能降级 + 界面明确提示
2. 创建对/删除对的幂等与异常（端口号冲突、驱动未加载）
3. 三方并发写入顺序（复用现有 FIFO 单测扩展为三方）
4. 设备数据同时到达 TCP 与本地口（字节级一致）
5. 本地软件反复开/关 COM11 的稳定性与缓冲溢出告警

## 6. 风险与限制

| 风险 | 等级 | 缓解 |
|---|---|---|
| com0com 驱动无 WHQL 签名，Win10/11 默认拒绝 | 高（阶段二） | 明确定位实验性功能；安装引导界面显著警示；不捆绑、不静默安装 |
| GPL 组件合规 | 中（阶段二） | com0com 仅作为独立第三方组件由用户自行安装，仓库与安装包不包含其任何文件 |
| 本地软件不在线时数据积压丢失 | 中（阶段二） | 界面计数告警 + 文档说明 |
| 用户误以为阶段一已提供虚拟 COM | 低 | 界面文案明确"本机直连需软件支持 Raw TCP/Telnet" |
